# Discovery-surface audit — ERC-8004, x402 Bazaar, MCP registry (2026-11-03)

Roadmap item B2 (`docs/research/2026-11-03-next-phase-roadmap.md`, Track B2):
"ERC-8004 agent metadata, x402 Bazaar listings, and MCP registry entries audited
as a set (descriptions, examples, pricing) so directory-indexed agents find the
guards; add a published 'build an agent in 10 minutes' quickstart per guard
family."

This document records what each discovery surface publishes today, the
inconsistencies found after the 2026-11-03 landing wave (A1 #360, C1 #364,
A2 #365, C2 #366), and the fix set shipped in the same PR.

## Findings

### F1 — x402 manifest lists 3 of 12 paid resources (stale, pre-dates C1/C2)

`.well-known/x402.json` (`updated: 2026-10-31`) lists only:
pre-trade, monad-lending-guard, `/api/mcp`.

Missing entirely: execution preflight, Base Lending Guard, Base Perp Guard,
Multichain EVM Lending Guard, Solana Lending Guard, Loopscale Vault Deposit
Guard, Verified Swap Intent, **Oracle Watch Window ($0.50/24 h, C1 #364)** and
**Position Lifecycle Bundle ($0.55/24 h, C2 #366)**. The two newest
recurring-revenue products are invisible to any agent that discovers Insight
through the manifest the ERC-8004 registration points at.

### F2 — agent8004.json: narrow description, stale network list

- `x402.networks` lists `8453, 137, 42161, 143, 56` — the manifest and the live
  402 quotes also advertise `eip155:999` (HyperEVM) and
  `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`. A keyless agent reading the ERC-8004
  file believes Solana settlement is unavailable.
- `description` describes only the pre-trade check; the guard families, Oracle
  Watch window, and Position Lifecycle bundle are absent, so directory-indexed
  agents cannot find the guards from the ERC-8004 metadata.
- `pricePerRequest: "0.02"` is correct as the per-call anchor (C3).
- `supportedTrust: ["reputation"]` stays as-is: `src/lib/erc8004/validationRegistry.ts`
  explicitly forbids claiming Validation Registry support until canonical
  deployments exist.

### F3 — agent-card.json (A2A): one skill, stale rail list

- `skills[]` contains only `pre_trade_safety_check`; every guard family and both
  bundle products are missing from the A2A surface.
- The top-level description says x402 runs on "Base, Polygon, Arbitrum One, or
  Monad" while its own `x402` extension description correctly lists BNB Chain and
  Solana mainnet too (and the manifest adds HyperEVM).
- The example string "10 independent providers" conflicts with the README
  ("13 oracle providers across 40+ blockchain networks").

### F4 — llms.txt: provider count and missing endpoints

- Header says "10 providers"; README and the roadmap say 13. The 13-provider
  claim is the established one; llms.txt is stale.
- The "Paid API (x402)" list has 5 entries; the lending/perp guard families,
  swap intent, and both 24 h products are absent.

### F5 — no published per-guard-family quickstart

`/docs/x402` quickstarts only the pre-trade GET and MCP tools/call. An agent
builder who wants, say, the Hyperliquid Perp Guard or the Position Lifecycle
Bundle has no copy-paste "first successful call in 10 minutes" path; each guard
family's parameters live only in OpenAPI.

### F6 — what is already consistent (no change needed)

- MCP catalog (`generatedCatalog.json` / `server-card.json`): all guard tools
  (`base_lending_guard*`, `monad_lending_guard*`, `multichain_evm_lending_guard*`,
  `solana_lending_guard`, `loopscale_vault_deposit`, `base_perp_guard*`,
  `hyperliquid_perp_guard*`, `oracle_watch`, `execution_preflight`,
  `pre_trade_safety_check`) are present with generated schemas; metering classes
  in `src/lib/billing/metering.ts` map every guard to C3 and receipts to C4.
- Bazaar per-route 402 descriptions in `resourceServer.ts` were updated per
  landing and describe every route, including the two plan-priced routes.
- Metering↔price consistency: 1 credit = $0.004 (`X402_CREDIT_USD`); C1=$0.002,
  C2=$0.008, C3=$0.02, C4=$0.04 agree across `llms.txt`, `/docs/x402`, and the
  MCP manifest description.
- OpenAPI (`public/openapi.yaml`) documents all new routes including the C2
  bundle sub-resources.

## Fix set shipped with this document

1. `.well-known/x402` + `.well-known/x402.json`: add the nine missing resources
   (F1) with per-route descriptions mirroring `resourceServer.ts`; plan-priced
   routes quote their plan amounts (Oracle Watch 500000 atomic = $0.50,
   Position Lifecycle 550000 atomic = $0.55); refresh `updated`.
2. `agent8004.json`: broaden the description to the guard/bundle catalog and add
   HyperEVM + Solana to `x402.networks` (F2).
3. `agent-card.json`: add one A2A skill per guard family plus the two 24 h
   products; align the rail list; correct the provider count; bump agent
   version (F3).
4. `llms.txt`: provider count → 13; add the missing paid endpoints (F4).
5. `/docs/x402`: add a "Guard family quickstart" section — one copy-paste
   "first call in ~10 minutes" block per family (REST GET/POST + MCP tool name),
   satisfying the roadmap quickstart requirement (F5).
6. `scripts/tests/x402-discovery-manifest.test.mts`: extend to pin the new
   resources, the plan amounts, and manifest↔manifest byte equality.

## Explicit non-goals

- No price changes (C3 pricing review is roadmap item C3, gated on 30 days of
  Bazaar telemetry).
- No Validation Registry claims in any surface (gated on canonical deployments).
- No MCP purchase path for the two 24 h products — both remain REST-first per
  the C1/C2 research docs; the MCP description keeps pointing at REST for
  window/bundle purchases.
- `public/skill.md` and the per-guard skill packages are Track B3, not B2.
